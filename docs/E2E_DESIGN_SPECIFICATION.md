# [E2E 개발 명세서] 코드로 디자인하는 디자인 시스템 (AtomSystem)

> **핵심 원칙**: 
> 1. 사용자는 마크다운(`.md`)으로 디자인 가이드를 제시하고, 엔진/에이전트는 디자인 토큰(`tokens.json`)을 컴파일한다.
> 2. 템플릿 코드는 1줄도 수정하지 않으며, 오직 시멘틱 토큰 변수(`var(--atom-...)`)에 의해 전체 스타일이 동적으로 결정된다.
> 3. 웹 대시보드, 가계부 앱, SaaS 웹앱, 모바일 웹 등 모든 템플릿의 디자인이 `.md` 파일에 따라 카멜레온처럼 전환된다.

## 1. 시스템 파이프라인 개요

```
[디자인 가이드 (.md)]
       ↓ (1. 토큰 파싱 & 생성)
[tokens/tokens.json (W3C DTCG)]
       ↓ (2. Style Dictionary 컴파일)
[build/css/_variables.css (CSS Custom Properties)]
       ↓ (3. 시멘틱 토큰 주입)
┌────────────────────────────────────────────────────────┐
│              동일한 단일 템플릿 소스코드                 │
│  - 가계부 앱 (Finance App)                             │
│  - 웹 대시보드 (Admin Dashboard)                        │
│  - 모바일 웹 (Mobile Viewport)                          │
└────────────────────────────────────────────────────────┘
       ↓ (4. Playwright 브라우저 E2E 검증)
[살아있는 명세서 (Living Documentation & Visual Report)]
```

## 명세 1: .md 기반 디자인 토큰 생성 및 컴파일

### 요구사항
- `presets/*.md` (예: `toss.md`, `daangn.md`, 커스텀 브랜드 가이드)에 기술된 브랜드 컬러, 타이포그래피, 곡률(Radius), 여백(Spacing), 그림자(Shadow) 규칙이 정량적 토큰 JSON 규격으로 파싱되어야 한다.
- `tokens/tokens.json` 파일이 갱신된 후, 토큰 빌드 스크립트 실행 시 CSS 변수(`var(--atom-...)`)가 즉시 갱신되어야 한다.

### 인수 기준 (Acceptance Criteria)
| 검증 항목 | Toss 프리셋 기준 | Daangn 프리셋 기준 |
| :--- | :--- | :--- |
| **Primary Color** | `#3182F6` (Vivid Blue) | `#FF6F0F` (Warm Orange) |
| **Surface/Card Radius** | `16px` ~ `20px` (볼드 라운딩) | `10px` ~ `14px` (소프트 라운딩) |
| **Typography Scale** | 모던 산세리프, 시원한 자간 | 따뜻하고 가독성 높은 본문 중심 |
| **Elevation / Shadow** | 소프트 레이어드 섀도우 | 은은한 로컬 커뮤니티 섀도우 |

---

## 명세 2: 시멘틱 변수 바인딩 & 테마 주입

### 요구사항
- 템플릿의 모든 컴포넌트(버튼, 카드, 테이블, 뱃지 등)는 **하드코딩된 스타일(예: `#3182f6`, `16px`)을 일절 사용하지 않는다.**
- 오직 시멘틱 CSS 변수만을 사용하여 스타일을 바인딩한다:
  - 배경/색상: `var(--atom-color-primary)`, `var(--atom-color-surface-bg)`
  - 라운딩: `var(--atom-radius-card)`, `var(--atom-radius-btn)`
  - 타이포그래피: `var(--atom-font-family)`, `var(--atom-font-size-title)`
  - 여백: `var(--atom-space-layout-gap)`
- 테마 전환(Query Param `?theme=toss`, `?theme=daangn` 또는 Data Attribute `data-atom-theme="..."`) 시 **새로고침 없이 실시간으로 전체 스타일이 리매핑**되어야 한다.

## 명세 3: 다중 템플릿 렌더링 검증 명세

### 3.1. 핀테크 / 가계부 앱 템플릿 (`/showcases/finance` 및 `/showcases`)

#### 시나리오 1-1: Toss 스타일 가계부
- **Given**: 사용자가 `theme=toss` 파라미터로 가계부 앱에 접속한다.
- **When**: 메인 화면의 잔액 카드와 [송금하기] 액션 버튼을 확인한다.
- **Then**:
  - [송금하기] 버튼의 `background-color`는 `rgb(49, 130, 246)`(`#3182f6`)이어야 한다.
  - [송금하기] 버튼의 `border-radius`는 `16px`이어야 한다.
  - 자산/잔액 카드의 모서리 곡률은 `20px`이어야 한다.

#### 시나리오 1-2: Daangn 스타일 가계부 (동일 컴포넌트)
- **Given**: 사용자가 `theme=daangn` 파라미터로 동일한 가계부 앱에 접속한다.
- **When**: 메인 화면의 잔액 카드와 [송금하기] 액션 버튼을 확인한다.
- **Then**:
  - [송금하기] 버튼의 `background-color`는 `rgb(255, 111, 15)`(`#ff6f0f`)로 즉시 변경되어야 한다.
  - [송금하기] 버튼의 `border-radius`는 `12px`로 변경되어야 한다.
  - 자산/잔액 카드의 모서리 곡률은 `14px`로 변경되어야 한다.

---

### 3.2. 관리자 웹 대시보드 템플릿 (`/showcases/dashboard`)

#### 시나리오 2-1: 브랜드 가이드에 따른 차트 및 요약 카드 반응
- **Given**: 대시보드 페이지에 서로 다른 테마를 주입한다.
- **When**: 상단 KPI 메트릭 카드 4개 및 사이드바 내비게이션을 렌더링한다.
- **Then**:
  - 사이드바 활성(Active) 메뉴 뱃지 색상이 테마의 Primary 색상과 일치해야 한다.
  - KPI 카드의 배경색, 보더 두께, 그림자가 `.md` 가이드의 토큰에 맞추어 전환되어야 한다.

---

### 3.3. 모바일 웹 뷰포트 템플릿 (모바일 화면 검증)

#### 시나리오 3-1: 모바일 규격 반응형 토큰 스케일 검증
- **Given**: 브라우저 뷰포트를 모바일 환경(`375px × 812px`, iPhone 규격)으로 설정한다.
- **When**: 템플릿 페이지에 접속한다.
- **Then**:
  - 모바일 하단 플로팅 액션 바(Bottom CTA)가 화면 하단에 고정 표시되어야 한다.
  - 모바일 폰트 스케일 및 터치 타깃 최소 높이(`min-height: 44px` 이상)가 보장되어야 한다.

## 명세 4: 디자인 가이드(.md) 임포트 및 마크다운 편집 화면

### 4.1. 요구사항
- 사용자는 디자이너 또는 AI Agent가 작성한 마크다운(`.md`) 디자인 가이드 문서를 업로드하거나, 화면에서 직접 작성하여 디자인 토큰을 동적으로 변경할 수 있어야 한다.
- **파일 업로드 기능**:
  - 드래그 앤 드롭 영역 또는 파일 선택 버튼(`input[type="file"][accept=".md,.markdown"]`)을 통해 로컬 `.md` 파일을 손쉽게 업로드한다.
  - 업로드된 파일의 마크다운 텍스트를 파싱하여 에디터 뷰에 즉시 반영한다.
- **마크다운 편집기(Editor)**:
  - 브라우저 내에서 직접 Markdown 텍스트를 편집할 수 있어야 한다.
  - 브랜드 색상(`primary: #3182f6`), 카드 곡률(`card: 16px`), 타이포그래피 등의 키워드를 분석하여 실시간 CSS 변수(`--atom-...`)로 컴파일한다.
- **프리셋 빠른 불러오기 (Preset Quick Loader)**:
  - 원클릭으로 토스 스타일(`toss.md`), 당근 스타일(`daangn.md`), 커스텀 템플릿(`custom-template.md`)을 로드하여 즉시 편집할 수 있어야 한다.
- **실시간 반영 및 내보내기**:
  - [토큰 적용하기 (Apply Tokens)] 버튼 클릭 시 새로고침 없이 즉시 오른쪽 미리보기 화면에 테마가 실시간 주입된다.
  - 작성된 가이드를 `.md` 파일로 다운로드하거나 컴파일된 `tokens.json`을 내보낼 수 있어야 한다.

### 4.2. 인수 기준 (Acceptance Criteria)
| 검증 항목 | 세부 조건 | 기대 동작 |
| :--- | :--- | :--- |
| **파일 업로드** | `.md` 파일 드래그앤드롭 또는 선택 | 파일 내용이 에디터에 로드되고 "파일이 성공적으로 로드되었습니다" 상태 표시 |
| **에디터 입력** | 에디터 텍스트 영역에 `#ff0055` 등 변경 입력 | 파싱 엔진이 변경된 컬러 코드를 감지하고 실시간 토큰 상태로 인식 |
| **프리셋 로드** | 'Toss', 'Daangn' 프리셋 버튼 클릭 | 해당 브랜드의 마크다운 전문이 에디터에 채워지고 프리뷰 테마가 즉시 동기화 |
| **토큰 주입** | [Apply / 적용] 실행 | `--atom-color-primary` 등 CSS 변수가 변경되어 템플릿 컴포넌트 스타일에 반영 |

### 4.3. E2E 테스트 검증 시나리오

#### 시나리오 4-1: 마크다운 파일 업로드 및 내용 반영
- **Given**: 사용자가 Studio 페이지의 `.md` 임포터 화면에 접속한다.
- **When**: 가상 `.md` 파일(예: Primary `#8b5cf6`가 명시된 마크다운)을 `input[type="file"]`에 업로드한다.
- **Then**:
  - 에디터의 텍스트가 업로드된 마크다운 내용으로 채워져야 한다.
  - 파싱된 Primary 색상이 `#8b5cf6`로 식별되어야 한다.

#### 시나리오 4-2: 에디터 텍스트 수정 및 실시간 토큰 주입
- **Given**: 에디터에 마크다운이 로드되어 있다.
- **When**: 사용자가 에디터의 Primary 컬러를 `#10b981`로 수정하고 [적용] 버튼을 누른다.
- **Then**:
  - 우측 프리뷰 화면의 버튼 또는 시멘틱 요소의 `background-color`가 `rgb(16, 185, 129)`(`#10b981`)로 변경되어야 한다.

## 5. E2E 테스트 실행 및 리포트 가이드

```bash
# 1. 디자인 토큰 컴파일
npm run token-build

# 2. E2E 디자인 명세서 테스트 실행
npx playwright test

# 3. 브라우저 인터랙티브 UI 모드로 디자인 실시간 확인 (개발 추천)
npx playwright test --ui

# 4. 시각적 Living Documentation 리포트 열기
npx playwright show-report
```
